## 🔴 Critical Issues (Phải sửa ngay)

### 1. Quả bom nổ chậm "Tràn bộ nhớ" (Memory Bomb) trong Thống kê
- **Vị trí:** `app/actions/contract-queries.ts` (Hàm `getContractStats`)
- **Nguy hiểm:** Khi DB RPC bị lỗi, hệ thống kích hoạt cơ chế fallback là **TẢI TOÀN BỘ hợp đồng trong DB** (không giới hạn số lượng) về phía server Node.js và dùng vòng lặp để tính tổng. Nếu studio có vài ngàn hợp đồng, hành động này sẽ gây tràn RAM, sập toàn bộ web, và làm chết các service khác.
- **Cách sửa:** Sửa logic fallback: Chỉ dùng aggregate query của Supabase (`select('...', { count: 'exact' })`) thay vì lấy toàn bộ record về lặp bằng JS.

### 2. Giam lỏng luồng chính khi Lưu Hợp đồng (Main Thread Blocking)
- **Vị trí:** `app/actions/contract-mutations.ts`
- **Nguy hiểm:** Quá trình bấm "Lưu" hợp đồng đang chạy đồng bộ quá nhiều việc: lưu DB, check trùng lịch váy, update lịch sử addons... Người dùng mạng yếu sẽ thấy hệ thống "treo" (loading xoay liên tục) và có rủi ro mất dữ liệu nếu request bị timeout giữa chừng.
- **Cách sửa:** Gói triệt để các tác vụ không ảnh hưởng hiển thị ngay (đồng bộ váy, addon, lịch) vào Background Tasks (`after` của Next.js hoặc Queue).

## 🟡 Warnings (Nên sửa)

### 1. Type "Mù" (TypeScript Any/Unknown Abuse)
- **Vị trí:** Xuyên suốt `contract-queries.ts`
- **Vấn đề:** Dev đang "lười" bằng cách ép kiểu dữ liệu thành `Record<string, unknown>`.
- **Hậu quả:** TypeScript trở nên vô dụng. Nếu đổi tên cột trong DB, code không báo lỗi đỏ, hệ thống vẫn build thành công nhưng user dùng sẽ thấy màn hình trắng xóa.
- **Cách sửa:** Bắt buộc định nghĩa Interfaces/Types rõ ràng theo chuẩn Database.

### 2. "God Object" Anti-pattern (File quá to)
- **Vị trí:** `app/actions/contract-mutations.ts` (> 700 dòng).
- **Vấn đề:** Một file nhồi nhét xử lý quá nhiều logic: váy, addon, audit log, v.v.
- **Hậu quả:** Rất khó bảo trì, khả năng cao gây lỗi ẩn khi nâng cấp tính năng.
- **Cách sửa:** Áp dụng Tái cấu trúc (Refactor), tách logic phụ trợ ra các file service độc lập (`dress-sync-service.ts`, `addon-sync-service.ts`).
