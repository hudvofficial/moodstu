# Audit Report - 2026-05-25

## Summary
- 🔴 Critical Issues: 2
- 🟡 Warnings: 2
- 🟢 Suggestions: 2

## 🔴 Critical Issues (Phải sửa ngay)
1. **Thư viện `next` chứa lỗ hổng bảo mật mức độ nghiêm trọng cao (High)**
   - **File:** `package.json`
   - **Nguy hiểm:** Tồn tại các lỗ hổng như HTTP request smuggling, bypass CSRF trong Server Actions và lỗi từ chối dịch vụ (DoS). Hacker có thể lợi dụng để vượt qua cơ chế bảo mật hoặc làm ngưng trệ hệ thống.
   - **Cách sửa:** Chạy lệnh `npm install next@latest` hoặc nâng cấp phiên bản `next` trong `package.json` lên bản vá an toàn hơn (`16.2.6` trở lên).

2. **Thư viện `serialize-javascript` có nguy cơ thực thi mã từ xa (RCE)**
   - **File:** `package.json` (phụ thuộc gián tiếp qua `@ducanh2912/next-pwa`)
   - **Nguy hiểm:** Hacker có thể lợi dụng lỗi trong RegExp/Date để thực thi mã độc hại trực tiếp trên server (Remote Code Execution) hoặc làm quá tải CPU.
   - **Cách sửa:** Chạy lệnh `npm audit fix --force` để cập nhật các package phụ thuộc lên phiên bản an toàn, hoặc nâng cấp cấu hình PWA phù hợp.

## 🟡 Warnings (Nên sửa)
1. **Thư viện `uuid` và `postcss` chứa lỗ hổng bảo mật trung bình (Moderate)**
   - **File:** `package.json` (phụ thuộc thông qua `@sentry/webpack-plugin` và Tailwind)
   - **Nguy hiểm:** `postcss` có nguy cơ bị tấn công XSS qua unescaped `</style>`. `uuid` thiếu kiểm tra Buffer bounds check.
   - **Cách sửa:** Chạy lệnh `npm audit fix` để nâng cấp lên các phiên bản vá tương thích không gây xung đột (non-breaking changes).

2. **Cảnh báo Dynamic Server Usage khi build**
   - **File:** `/finance/expenses`
   - **Chi tiết:** Trang `/finance/expenses` không thể render tĩnh (prerender static) do sử dụng `cookies` để kiểm tra quyền truy cập (Auth).
   - **Đánh giá:** Đây là hành vi đúng chuẩn kỹ thuật của Next.js khi bảo mật trang phía server. Tuy nhiên, nên đảm bảo bọc Suspense quanh các phần dữ liệu động nếu muốn cải thiện UI/UX.

## 🟢 Suggestions (Tùy chọn)
1. **Cài đặt Rate Limiting cho API Routes**
   - **Đường dẫn:** Các API nhạy cảm như `/api/auth/*`
   - **Đề xuất:** Cấu hình Rate Limit (ví dụ qua Middleware hoặc Upstash) để ngăn chặn các cuộc tấn công Brute-force/Spam API đăng nhập.

2. **Dọn dẹp các script debug trong thư mục gốc**
   - **Chi tiết:** Có một số file script test đơn lẻ (`test-google-direct.js`, `test-drawer.ts`, `test-db-kieuan.ts`) nằm ở thư mục gốc.
   - **Đề xuất:** Di chuyển chúng vào một thư mục riêng (như `scripts/test/`) hoặc xóa bỏ khi không còn dùng đến để giữ project sạch sẽ.
